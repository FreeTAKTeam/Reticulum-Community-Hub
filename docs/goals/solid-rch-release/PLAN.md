## Design decisions and evidence log

- Use the sibling's Rust engineering principles: regression first, minimal cohesive refactor when needed, explicit failures, bounded ownership and operator evidence. Research nontrivial pattern choices with primary Rust/Tokio/axum/native-tls documentation and record relevant trade-offs here.
- Current `main` already has fixes for actor queue expiry, malformed command quarantine, team scope, and topic subscriptions. Integrate those; do not duplicate them on the older checkout.
- The ordinary server-only gate is HTTP smoke. Its green result does not prove southbound runtime. Separate real loopback daemon and extracted-package evidence are required.
- PRE review: partially aligned, no blocker to alignment/reproduction. All required corrections are incorporated below before behavior changes.
- Bootstrap is limited to public documentation/app metadata/UI assets, local first-run setup status and completion when no credential exists. Other protected HTTP routes and all internal/WS streams require credentials even before enrollment. Once any credential exists, setup completion requires it; unknown peers never receive local authority. Adapt operator/CLI/UI fixtures explicitly rather than introducing a test-only production bypass.
- Durability acceptance includes competing same-entity read/modify/commit commands and accepted updates surviving restart. Establish one owner for the complete mutation sequence, then commit before projections/events. Distinguish a committed write from a subsequent notification failure.
- Upload baseline: primary axum documentation confirms a 2 MiB default body bound, contradicting the unlimited-body assertion in #223. Reproduce the documented 8 MiB usability mismatch; enforce finite aggregate, field and file-count limits when allowing larger uploads. Verify legitimate >2 MiB and exactly 8 MiB files, over-limit 413, and chunked rejection.
- Required release verification also includes `scripts/check-rust-module-size.ps1`, installation/launch helpers and packaged configuration, authenticated setup, persisted state after restart and daemon diagnostics. Linux evidence remains distinct from hosted Windows/macOS/ARM results.
- Primary design references consulted: [axum Multipart](https://docs.rs/axum/latest/axum/extract/struct.Multipart.html), [DefaultBodyLimit](https://docs.rs/axum/latest/axum/extract/struct.DefaultBodyLimit.html), [tower-http AllowOrigin](https://docs.rs/tower-http/latest/tower_http/cors/struct.AllowOrigin.html), [Tokio spawn_blocking](https://docs.rs/tokio/latest/tokio/task/fn.spawn_blocking.html), [native-tls builder](https://docs.rs/native-tls/latest/native_tls/struct.TlsConnectorBuilder.html), [Tauri CSP](https://v2.tauri.app/security/csp/). ### Durability and lifecycle checkpoint

- Six initial durability regressions failed before correction, then passed. Review reproduced four more failures: attachment bytes destroyed before a rejected metadata delete, failed unban published to live policy, a delivered receipt overwritten by stale retry work, and corrupt attachment rows silently reported as empty. Their corrections pass focused regressions.
- Core command transactions reserve `BEGIN IMMEDIATE` before reading and retain ownership through commit. Accepted deltas publish afterward; rejected/domain/storage errors roll back. Consistent multi-table reads use a read transaction. Direct marker/zone and attachment patches read their durable row inside the write reservation, preserving disjoint updates across independent states and preventing deleted records being recreated by stale patches. Topic deletion detaches attachment links in the same transaction.
- Message transitions stage candidates under the existing write guard, commit before publication, and validate current eligibility/attempt under that guard. Receipts win over stale dispatch completion/retry. Moderation, announce identity projections, roster presence and removals commit before becoming visible; announces cannot overwrite an existing moderation decision. Malformed attachment snapshots now return an error.
- A true deferred-constraint COMMIT failure regression proves rollback and subsequent reservation recovery. Restart assertions cover mission patches, telemetry ordering, failed moderation, delivery receipts and marker/zone patches. The historical server library checkpoint passed 387 tests, with one live test ignored; the final run after marker-idempotency and callback additions passes 404 library tests, with the live test exercised separately.
- Two lifecycle regressions failed before fixes. Terminal process exit is separate from resumable `/Control/Stop`, wakes long sleeps, and drains owned workers before SDK/daemon cleanup. A timed-out blocking tick is retained and joined before another starts. Cleanup attempts the daemon stop even after control-lock or SDK failure. Periodic announce survives control pause/resume. Six targeted lifecycle tests pass, including real owned child-process cleanup.
- Primary lifetime references: [Tokio Notify](https://docs.rs/tokio/latest/tokio/sync/struct.Notify.html), [spawn_blocking](https://docs.rs/tokio/latest/tokio/task/fn.spawn_blocking.html), [rusqlite Transaction](https://docs.rs/rusqlite/latest/rusqlite/struct.Transaction.html), [thread park_timeout](https://doc.rust-lang.org/std/thread/fn.park_timeout.html).
