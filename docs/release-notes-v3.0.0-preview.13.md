# RCH Rust v3.0.0-preview.13 testing release

Preview.13 includes the issue #242 resource-efficiency fixes in RCH and the bundled ZeroMQ-capable `reticulumd`. It retains the issue #238 inbound delivery and issue #241 sustained polling/restart fixes. RCH backend source is qualified at `e159b27ecb7c6da9ae559e981870ee3a722c792e`; LXMF-rs 0.13.0 is pinned to `67e63710986111fbf671dd3cf823d57615f8596f`, with SDK configuration 2 / contract v2.6. Each archive records its exact release commit and daemon source in `release-manifest.json`.

For Linux x86_64, download `rch-rust-full-linux-amd64-v3.0.0-preview.13.tar.gz` and its adjacent SHA-256 file. Replace both RCH and the daemon with this matching pair: the older standalone rch241.2 daemon does not contain the #242 index fix. The server archive also includes the built UI, TAK service, configuration templates and service helpers. Point `--ui-dist-path` at the archive's `ui/` directory and preserve your existing daemon endpoints, destination configuration, credentials and identities. Other server packages cover Windows x64, macOS x64/arm64 and Raspberry Pi 64; desktop installers remain preview artifacts.

Stop all services and back up runtime state before upgrading. RCH migrates its database to schema 4 and creates `<database>.pre-migration-v4.bak` for a schema-3 database. Do not run old and new RCH writers against the same database. To downgrade, stop services and restore the schema-3 backup; writes made after upgrading will be lost. See the [migration and rollback instructions](issue-242-resource-efficiency.md) before testing with existing data.

RCH now uses bounded announce lookups, indexed diagnostic summaries and persisted announce projections. The daemon adds an index for completed propagation-mark lookups. A paired 30-minute test with 100,000 retained announces, four persisted inbound messages and a daemon restart passed. RCH median RSS fell from 706.1 to 139.8 MiB, CPU from 11.41% to 1.47% of one core, and diagnostics p95 from 227.7 to 4.6 ms in that fixture. The server release gate and both repositories' source CI passed. These results do not establish resolution of the original production CPU/memory report or behavior under a 2 GiB memory limit; issue #242 remains open for production acceptance.

After installation, check authenticated `/Status` and `/diagnostics/runtime`, daemon `/readyz`, authenticated announce, and fresh persisted inbound messages beyond 15 minutes and after a daemon restart. Capture process memory and CPU for comparison with your deployment. Native desktop interaction and external TAK/REM hardware acceptance are separate from package-build verification.
